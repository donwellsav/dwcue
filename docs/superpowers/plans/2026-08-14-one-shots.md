# One Shots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan.

**Goal:** Replace the fixed Cart Player with a safe One Shots panel backed by canonical playlist cues.

**Architecture:** Add optional One Shot metadata to audio cues, migrate legacy Cart documents at the server trust boundary, derive panel tiles from the playlist, and reuse the existing playback/ducking/end-behavior engine contracts.

**Tech Stack:** Vue 3/Nuxt 4, TypeScript, Electron, C++20, nlohmann JSON, CMake assertion tests.

## Global Constraints

- Never delete a cue when removing its One Shot designation.
- Preserve all legacy Cart media and cue settings during migration.
- Do not expose engine behaviors that do not exist.
- Keep old Cart document fields and IPC names as read-compatible scaffolding for this release; the visible product and new writes use One Shots.
- Do not touch unrelated untracked build artifacts.
